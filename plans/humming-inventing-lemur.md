# 設計書（DD）仕様表示順序の変更

## Context

システム設計書（DD）の編集画面において、仕様項目の表示順序を変更したいとの要望。

### 現状の問題
- 現在の順序: エントリポイント → 入力スキーマ → **入力項目** → **コアロジック** → 出力スキーマ → **出力項目** → ...
- 望ましい順序: エントリポイント → 入力スキーマ → **コアロジック** → 出力スキーマ → **入力項目** → **出力項目** → ...

### 変更の目的
仕様の論理的な流れに合わせて表示順序を整理する：
1. 入力側の定義（入力スキーマ）
2. 処理の定義（コアロジック）
3. 出力側の定義（出力スキーマ）
4. 入力の詳細（入力項目）
5. 出力の詳細（出力項目）

---

## 実装計画

### 変更内容

`DesignDocumentCard.tsx` の `return` 文内（839行目以降）で、`<FoldableStructuredSection>` コンポーネントの並び順を変更する。

**変更対象セクション:**
- **入力項目（データ）** (1613行目付近)
- **コアロジック** (1634行目付近)

**変更方法:**
1. 「入力項目（データ）」セクションを後ろに移動（出力スキーマの後）
2. 「コアロジック」セクションを前に移動（入力スキーマの後）

### 変更後の順序

```
1. エントリポイント (840行目 - 変更なし)
2. 入力スキーマ (851行目 - 変更なし)
3. コアロジック (元1634行目 - 入力項目の前に移動)
4. 出力スキーマ (元1905行目 - 変更なし)
5. 入力項目（データ） (元1613行目 - 出力スキーマの後に移動)
6. 出力項目（データ） (1937行目 - 変更なし)
7. 副作用 (変更なし)
8. 例外 (変更なし)
9. 非機能要件 (変更なし)
```

### 修正ファイル

### 影響範囲

- **UI変更**: あり（表示順序のみ、機能への影響なし）
- **データ変更**: なし
- **DB変更**: なし

## 検証方法

1. 開発サーバーが起動していることを確認
2. システム領域一覧から任意のシステム機能を開く
3. 設計書タブを開き、セクションの順序を確認
4. 以下の順序で並んでいることを確認:
   - エントリポイント
   - 入力スキーマ
   - **コアロジック** ← 入力項目の前になっていること
   - 出力スキーマ
   - **入力項目（データ）** ← 出力スキーマの後になっていること
   - 出力項目（データ）
   - 副作用
   - 例外
   - 非機能要件

---

## 注意点

- 各セクションは `<FoldableStructuredSection>` で独立してラップされているため、セクション単位の移動は安全
- 各セクション内のロジックや状態管理には変更を加えない
- エントリポイント、副作用、例外、非機能要件の位置は変更しない
