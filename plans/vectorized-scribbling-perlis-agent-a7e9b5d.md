# /chat 画面 システム機能・要件カード表示仕組み 調査計画

## 調査概要
/chat 画面（localhost:3000/chat）におけるシステム機能・システム要件のカード表示仕組みを徹底的に調査する。

## 調査観点と子エージェント

### 観点1: チャット画面の基本構造とデータフロー
**タスクID**: #3
**担当**: 子エージェント1
**調査内容**:
- app/(with-sidebar)/chat 配下のページ実装
- app/api/chat/route.ts のAPI実装
- チャットメッセージのデータフロー
- ストリーミングレスポンスの仕組み

### 観点2: AIエージェントとツールの実装
**タスクID**: #4
**担当**: 子エージェント2
**調査内容**:
- lib/mastra/agents/ 配下のエージェント定義
- lib/mastra/tools/ 配下のツール実装
  - system-draft.ts
  - br-draft.ts
  - system-domains.ts
  - system-functions.ts
  - system-requirements.ts
- カード表示用のデータ構造

### 観点3: カード表示コンポーネント
**タスクID**: #1
**担当**: 子エージェント3
**調査内容**:
- components/ai-chat/ 配下の全コンポーネント
- カード形式のUIコンポーネント
- 業務タスク照会画面風のカード表示
- progress-stepsコンポーネント

### 観点4: システム機能・システム要件の登録フロー
**タスクID**: #2
**担当**: 子エージェント4
**調査内容**:
- lib/data/system-functions.ts
- lib/data/system-requirements.ts
- lib/data/system-domains.ts
- カード表示から実際の登録までのフロー
- ドラフト状態から確定状態への遷移

## 横断分析項目
各子エージェントの結果から以下を抽出・統合する:

1. **カード表示のトリガー条件**
   - どのタイミングでカードが表示されるか
   - どのようなデータ構造でカードが生成されるか

2. **システム機能・要件カードの特徴**
   - 業務タスクカードとの違い
   - 固有のプロパティやアクション

3. **データフローの全体像**
   - ユーザー入力 → AI処理 → カード生成 → 登録確定

4. **実装パターン**
   - カード表示の共通化されたパターン
   - 種類別のカスタマイズポイント

1. 各観点の詳細調査レポート
