# ユーザーストーリードキュメント作成計画

## Context

現状、このプロダクト（要件管理DB）には「ユーザーがなぜ・どう使いたいか」を体系的に記述したドキュメントが存在しない。PRD.md のセクション9に画面構成と利用フローはあるが、操作手順の羅列であり、ユーザーの動機・期待・体験が記述されていない。

**目的**: ユーザーストーリードキュメントを「北極星」として作成し、以下の2つの用途に使う：
1. **UI/UXレビュー基準**: 実装済みの仕様がストーリーに沿っているかチェック
2. **開発方向性ガイド**: 北極星と比べて備わっていない仕様の差分を特定

## 成果物

**ファイル**: `docs/user-stories.md`（単一ファイル。大きくなったら分割を検討）

## ドキュメント設計

### アプローチ: ユーザーストーリー + UXチェック基準

ジャーニー（ワークフロー）単位でストーリーを整理し、各ストーリーにUXチェック基準を付与する。

### ドキュメント構成

```
1. ペルソナ定義
2. ジャーニーマップ（概要）
3. ジャーニー別ユーザーストーリー
   J1: プロジェクトの立ち上げ
   J2: 業務要件の定義（BT/BR）
   J3: システム要件の定義（SF/SR/AC）
   J4: 設計書の作成（DD）
   J5: AIを活用した要件登録
   J6: 要件間リンクと品質管理
   J7: 変更管理（CR/影響調査）
   J8: エクスポートと外部連携
4. 横断的UX原則
```

### ペルソナ（1人全役パターン）

```
要件管理者（ソロ開発者）
- コーディングエージェントを活用して受託スクラッチ開発を行う
- PO帽（業務要件定義、変更判断）、SE帽（システム要件・DD）、AI運用帽（チャット、エクスポート）を使い分ける
- コアニーズ: 書き方を考える時間の最小化、影響見落ち防止、1人品質維持
```

### 各ストーリーのフォーマット

```markdown
### S{J}.{N}: {やりたいことの端的な表現}

**ストーリー:**
要件管理者として、{何をしたい}。
なぜなら{理由}だから。

**前提状況:**
- {このストーリーの開始条件}

**期待するUX:**
- {ユーザーが感じるべき体験}

**UXチェック基準:**
- [ ] {UIで確認すべき具体的な項目}
```

### 横断的UX原則（5つ）

| 原則 | 内容 |
|------|------|
| P1: 現在地が常にわかる | パンくずリスト / サイドバーハイライト |
| P2: 次にやるべきことが明示される | 空状態ガイダンス、完了後の次アクション |
| P3: 入力は最小限、AIが補完する | 必須フィールド最小化 |
| P4: やり直しが怖くない | 草案→確定の2段階、確認ダイアログ |
| P5: 全体の健全性が見える | ヘルススコア、疑義リンク可視化 |

### 既存ドキュメントとの役割分担

| ドキュメント | 問い | 位置づけ |
|---|---|---|
| **user-stories.md（新規）** | なぜ・どう使いたいか | 最上位（北極星） |
| **PRD.md** | 何をするか | 中位（仕様） |
| **設計書（design/）** | どう実現するか | 下位（実装） |

user-stories.md は PRD の上位に位置づける。ストーリーが変わらないのにPRDが変わるのはOK。ストーリーが変わるならPRDも見直す。

## 実装手順

### Step 1: ドキュメント骨格の作成

`docs/user-stories.md` を作成し、以下を記述:
- ペルソナ定義
- ジャーニーマップ（概要、J1〜J8の一覧と依存関係）
- 横断的UX原則（P1〜P5）

### Step 2: 各ジャーニーのストーリー記述

PRD.md（特にセクション9の利用フロー）と既存の画面実装を参照しながら、各ジャーニーのストーリーを記述する。

**参照すべきファイル:**
- `docs/PRD.md` セクション9（画面構成と利用フロー）
- `docs/PRD.md` セクション3（要件記述仕様）
- `docs/PRD.md` セクション4（変更管理）
- `docs/PRD.md` セクション5（AI機能）
- `docs/overview/PRD_overview.md`（概要版）
- `app/(with-sidebar)/` 配下の各ページ実装（実際の画面構成確認用）

**ジャーニー別のストーリー概算:**

| ジャーニー | 想定ストーリー数 | 主な内容 |
|---|---|---|
| J1: プロジェクト立ち上げ | 3-4 | PR設定、BD作成、SD作成 |
| J2: 業務要件定義 | 3-4 | BT作成、BR作成、ゴール・制約記述 |
| J3: システム要件定義 | 3-4 | SF作成、SR作成(type別)、AC作成(GWT) |
| J4: 設計書作成 | 4-5 | DD作成、構造化I/O、コアロジック、エントリポイント |
| J5: AI活用要件登録 | 3-4 | BT/BR草案、SF/SR/AC一括、DD草案、レビュー・確定 |
| J6: リンクと品質管理 | 3 | realizesリンク、概念辞書、ヘルススコア |
| J7: 変更管理 | 3-4 | CR起票、影響調査、疑義リンク解消 |
| J8: エクスポート | 1-2 | エクスポート実行 |

合計: 約25-30ストーリー

### Step 3: UXチェック基準の付与

各ストーリーにUXチェック基準（チェックボックス形式）を追加。現在の実装状況も考慮して、達成済み/未達成を初期状態で記録。

### Step 4: CLAUDE.md の更新

`CLAUDE.md` の「設計書参照・更新ルール」セクションに `docs/user-stories.md` を追加し、UI/UX改修時の参照先として明記する。

## 難易度

```
難易度: ★★☆
根拠: 1 file, ~500-800 lines, PRDからの抽出+再構成
リスク: ストーリーの粒度調整（細かすぎるとメンテコスト増、粗すぎるとレビュー基準にならない）
```

## 検証方法

1. ドキュメント完成後、J1（プロジェクト立ち上げ）のUXチェック基準を使って実際の画面をレビューしてみる
2. チェック基準が「チェックできる」粒度になっているか確認
3. 過不足があれば粒度を調整
