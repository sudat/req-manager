# マネージドスクラッチ ビジネスモデル＆マーケティング戦略 議論サマリ

## 議論の目的と到達点

須田のマイクロ法人が提供する「要件管理DB × AIコーディングエージェント」を活用したスクラッチ開発サービスについて、kintone（内製・外注）を主要な比較対象としたビジネスモデル設計とマーケティング戦略を議論した。

到達した結論：kintoneの内製コスト・外注コストを可視化し、「同じ金額帯でプロが全部やる。しかも機能制限なし」というポジショニングでマネージドスクラッチを訴求する。

## 1. ビジネスモデル：マネージドスクラッチ

### コンセプト

スクラッチ開発をSaaS的な月額課金で提供する。月額利用料のみ。解約自由。

### 契約

- サービス利用契約に準じたクライアントへのサービスの提供を実体とする。
- アプリは私が契約するホスティング・DBに保管する。
- あくまでアプリの所有権は私にある。
- 単一クライアントの要件をベースとしたサービスを構築しつつ、請負契約・委託契約ではないため、クライアントの真の要件に対するGapに対して責任が生まれない。
- 書面として提供するサービスのマニュアル・仕様書と実装が異なる点についてのみクライアントは不服を申し立てることが可能。
- クライアントの真の要件とサービスの仕様が異なる場合には、クライアントは「仕様変更を要望する」ことは可能。しかし、委託ではないのでそれを引き受けるかどうかは私に完全な権利がある。
- 通常の請負契約やベンダ側の責任や準委任契約における善管注意義務の責任はクライアント側がコスト面でリスクを背負っていることに起因するベンダ側への牽制の意味合いが強いが、当契約は月額制・解約自由であるためむしろクライアント側に有利であるためベンダ側が法的に重い責任を背負っていないと考える。ただしサービス提供者としてデータやインフラの管理義務や責任はもちろん保持する。

### 料金体系

月額は機能数 * 2.5万円（複雑度で傾斜あり）に基づいて設定する。

- 10機能/月額25万円（12ヶ月回収で300万円相当）
- 20機能/月額50万円（12ヶ月回収で600万円相当）
- 全機能リリース後、6カ月ごとに以下の特典をクライアントに与える。
  - 月額割引：それ以降の月額を5%だけ割り引く。（初期の月額に対する5%なので単利計算）
  - 機能追加：機能数×20%のクレジットを提供する。1クレジット=1機能追加が目安。

## 2. マーケティング戦略

### 設計思想（入口と出口の強化）

- マイクロ法人、実績なしという自分自身の集客力の弱さを踏まえて集客力（マーケティング）の強化と、継続課金が収益性のカギであるマネージドモデルのため解約率の抑制を最優先とする。

- 集客力の強化のためにはカギとなるメッセージを作る。
  - 現状の業務非効率に課題感がありkintoneなど何らかの低廉なツールを使って業務効率化を検討中のユーザをターゲットとする。
  - ターゲットの課題感は「kintoneで実現できるのか」「kintoneで実現できるとして内製は現実的なのか」「外注はむしろ高いのではないか」。
  - この課題感に対して「kintoneでは実現範囲が限定されているし割高」「私のマネージドスクラッチであればkintoneより割安かつ機能性が優れている」「解約も自由」「継続利用で最大、月額料金も半額」というメッセージで訴求する。
- 獲得したクライアントの本番稼働後は解約率の抑制がカギだがそのための仕組みとして継続利用による割引か機能追加を提供する。
  - 安さを重視するクライアントに対しては半年おきに5%の月額割引を提供する。この割引により「一見ほかのサービスに乗り換えればコストは抑えられそうだが段階的に月額料金は下がるし敢えてリプレイスする必要はあるか？」と踏み止まらせる。
  - 業務適合を重視するクライアントに対しては半年おきに機能追加に使えるクレジットを提供する。このクレジットにより「今は不満がいくつかあるが継続的に改善してくれるから敢えてリプレイスする必要はあるか？」と踏み止まらせる。
- 割引、またはクレジットは半年ごとにクライアントと現状のサービス・機能を振り返る機会を作る。「次は何を改善するか」の会話は業務課題のヒアリングそのものであり、アップセルの種まきでもある。

### マーケティング上の訴求

クライアント向けには以下の4点セットで説明する。

```
① 初期費用ゼロ・月額制・解約自由
② 継続利用で段階的に月額を値下げ・最大半額
③ 半年ごとのバージョンアップも可能（月額に含む）
④ 毎月の定例で改善を継続提案
```

②の「最大半額」はマーケティングのキーワードとして機能する。③④はSaaSにもSIerにもない差別化要素。


### カスタマーサクセスと月例打合せ

本稼働後は運用上の不満が表出しやすいため月例MTGを実施する。
クレジットが付与される6カ月経過時点までは改修要望は個別見積（月額加算）となる。

### クレジットの考え方

#### クレジット消費カタログ

クレジットは改修の複雑度に応じて0.1単位で消費する。カタログを事前にクライアントへ提示し、「この改修にいくらかかるのか」を見える化する。

| 改修内容 | 消費クレジット |
|---|---|
| ラベル・文言変更 | 0.1 |
| 表示項目の追加・削除 | 0.2 |
| バリデーションルール変更 | 0.2 |
| 帳票レイアウト変更 | 0.3 |
| バッチロジック変更 | 0.3 |
| 画面内の計算ロジック追加 | 0.3 |
| 既存画面への入力セクション追加 | 0.5 |
| 新規帳票追加（簡易） | 0.5 |
| 外部連携の改修 | 0.5 |
| 新規画面追加（簡易） | 0.8 |
| 新規バッチ処理追加 | 0.8 |
| 新規画面追加（複雑） | 1.0 |

※上記はあくまで目安。実際の消費量は改修ごとにSuda側が見積もり、月例MTGで合意する。

クレジット制は透明性を欠くと「結局いくらかかるのか分からない」というSIerと同じ不信感を生む。0.1単位のカタログを事前提示することで、クライアントは自分の改修要望がどれくらいのクレジットを消費するか予測できる。

これは期待値の管理ツールであると同時に、クレジット消費の「値ごろ感」を醸成する仕掛けでもある。「ラベル変更が0.1で済むなら、0.7クレジットで7箇所直せる」という計算がクライアント側で成り立てば、クレジットの価値を実感しやすい。

#### クレジットの運用ルール

- クライアントからの改修要望は月例MTGで受け付け、クレジット範囲内で対応
- 改修の実作業はフリーランスに委託。Sudaは提案・見積もり・品質管理を担当

- セグメント2（kintoneでは無理、SIerに頼むしかない）：月額22万は明らかに安すぎる。SIer発注なら1000-3000万円。月額50万円でも3年累計1150万円でSIerの半額以下。

### kintoneでは実現困難な機能

| 制約 | 理由 |
|------|------|
| リアルタイム在庫管理 | トランザクション制御が弱い。同時更新で数量不整合リスク |
| 複雑な価格計算 | JSで書けるが保守不能化するリスク |
| 基幹とのリアルタイム連携 | CSV日次バッチが現実的上限 |
| 帳票の細かいレイアウト制御 | プリントクリエイターの限界 |
| 大量データ高速処理 | 1アプリ50万レコード上限、データ蓄積でレスポンス劣化 |
| フィールド単位の権限制御 | JavaScript頼みで煩雑 |

### マネージドスクラッチ（813万円/3年）なら上記に加えて実現可能

- リアルタイム在庫（PostgreSQLトランザクション制御）
- 複雑な価格計算エンジン（サーバーサイドロジック）
- 基幹とのAPI双方向リアルタイム連携（Next.js API Routes + Edge Functions）
- 帳票の完全制御（React-PDF / Puppeteer）
- 大量データ対応（PostgreSQL、レコード上限なし）
- 細かい権限制御（Supabase RLS）
- リアルタイムダッシュボード（Recharts等、プラグイン不要）
- モバイル最適化UI（レスポンシブ、kintoneモバイルの制約なし）

## 6. 競合比較の使い方（コンテンツ戦略上の注意）

### kintone名指し批判の回避

サイボウズはエバンジェリスト・コミュニティの結束が強い。kintoneを名指しで批判するとSNS上でネガティブな反応が広がるリスクがある。

比較は「kintone vs スクラッチ」ではなく「内製 vs 外部委託」というフレームで行う。kintoneはその一例として触れる程度にとどめる。「kintoneが悪いのではなく、使い方の問題」というトーンを一貫させる。

### 記事構成案

タイトル：「kintoneで業務システムを作るのが本当にベストなのか？」

3パターン比較で掲載：
- ①kintone内製パターン
- ②kintone外注パターン
- ③マネージドスクラッチ（須田に依頼）パターン

②の存在がこの比較の鍵。①と③だけだと「kintone（安い）vs スクラッチ（高い）」の二択に見えるが、②を挟むことで「kintoneも外注したら高い。しかも機能制限がある」という事実が可視化される。②は③の引き立て役として機能する。

### 本質的な比較軸

最終的にクライアントが比べているのはkintoneではなく「今のExcel運用を続けるコスト」と「システム化するコスト」。月額22万円のマネージドスクラッチは、派遣社員1名の人件費（月35-50万円）や属人作業の年間コスト（500-1500万円）と比較されるべきであって、kintoneのライセンス費用と比較されるべきではない。

## 7. 顧客獲得戦略

### ターゲット顧客の思考パターン

A層（実行したいがパートナーが見つからない）：
- A1：SIer見積もりが合わない → Lプラン相当で刺さる
- A2：SaaSが要件に合わない → 機能制限なしが刺さる
- A3：kintone/Power Appsがあるが社内リソースがない → マネージド全般で刺さる
- A4：問題は言語化できるが解決パターンを知らない → 業務診断で刺さる
- A5：SIerプロジェクト失敗のトラウマ → フェーズリリース・月額制で刺さる

B層（問題は認識しているが解決策が不明）：
- B1：他社事例が見たい → note記事で刺さる
- B2：解決手段を知らない → コンテンツマーケティング全般
- B3：問題の根本原因がわからない → 業務診断で刺さる
- B4：判断基準がない → kintone vs スクラッチ比較記事で刺さる

D層（知識はあるが組織的に動けない）：
- D1：IT投資予算がない → 月額100万円以下の梅プランが部長決裁圏内
- D2：プロジェクトオーナー不在 → 「クライアント作業ゼロ」が刺さる
- D3：意思決定者の優先度が別にある → 「小さく始めて実績を作る」
- D4：部門間対立 → スコープを狭めて単一部門で完結
- D5：失敗リスクを取りたくない → 「N社で導入実績あり」が安全な判断材料

### kintone比較が効く相手

工数をコストとして認識している経営者・CFO。業務効率化を検討している時点で、この認識はある。「社員の人件費はタダ」と考える人は、そもそも業務効率化を考えない。よってTCO比較は正しい訴求軸。

### 集客チャネルとの対応

- note記事（テーマ⑧ kintone vs スクラッチ）：B4層に直接刺さる。3パターン比較表をそのまま掲載
- X：note記事からフックになる一文を切り出して投稿
- LinkedIn：税理士・社労士・中小企業診断士へのリーチ（退職後に本格稼働）
- リファラル：既存クライアント経由の紹介ルートを構築
