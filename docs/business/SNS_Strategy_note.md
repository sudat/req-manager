## 1. なぜnoteが主戦場なのか

中堅企業の経営者・事業部長が情報収集するとき、Xの短文では意思決定の参考にならない。YouTubeは制作コストが高すぎる。noteの長文記事は検索にも引っかかり、「この人は分かっている」という信頼構築に最も効率が良い。

さらに重要なのは、コンテンツマーケティングには半年〜1年のリードタイムがあるということ。退職後に記事を書き始めても、検索流入が安定するのは半年後。だからこそ在職中からストックを準備し、退職直後に一気に公開する戦略を取る。

## 2. 記事の基本方針

### コアメッセージ（v3で改訂）

「ERPやSaaSで効率化した"つもり"の企業に残る業務のスキマを、構造的に特定し、初期費用ゼロの月額制で確実に埋める。」

v1の「ケイパビリティを叫ばない」は維持しつつ、「パッケージのスキマ専門家」というポジショニングを記事全体に貫く。加えて、マネージドスクラッチモデル（初期費用ゼロ・月額制・解約自由）を提供形態として明示し、「スクラッチ開発＝高い・リスクが大きい」という先入観を崩す。

### ベンダーニュートラルの姿勢（変更なし）

SaaSやETLが最適ならそちらを提案する記事を書く。「スクラッチに固執しない」スタンスが逆説的に信頼を生む。

### 書くべきコンテンツは4種類（v3で1種類追加）

1. 「スキマ業務の実態暴露」系：読者が「うちもそうだ」と感じる業務課題の描写。AsIs/ToBeを描いてCxO/部長クラスの視座で課題解決後の姿を見せる。
2. 「実際にコーディングエージェントで作ってみた」系：スキマ業務をシステム化するプロセス。業務要件→システム要件→実装の変換プロセスを見せる。金額表現は「月額〇万円で使える」に統一。
3. 「AI時代のコンサルタント価値」系：AIがコードを書く時代に、人間が担うべき役割を問う。ポジショニングの知的根拠を提供する記事。
4. （v3追加）「マネージドスクラッチの仕組み解説」系：初期費用ゼロ・月額制・解約自由のモデルがなぜ成立するのか、買い切り開発との違い、kintone等との3年TCO比較を解説する記事。

### 書き方の鉄則（変更なし）

- 記事の前半で「なぜこの問題がERPやSaaSだけでは解決しないのか」を業務構造から説明
- 後半で打ち手を見せる
- AsIs/ToBe業務フローを随所に織り込む

### 公開頻度（リソース制約を反映して改訂）

### 記事構成テンプレート（変更なし）

## 3. 記事テーマ一覧

### カテゴリ1：スクラッチ優位が明確なテーマ（主力）

#### テーマ①：月次決算を早期化できない本当の理由 ← 最優先

- 対象読者：経理部長・管理会計担当（年商50-500億円規模）
- AsIs：ERPから数字は出るが、連結や管理会計の組み替え、部門配賦、経営レポート作成でExcelが介在。月次クローズに10営業日。
- 痛み：配賦ロジックやマッピングルールが企業ごとに全く違うのでSaaSの標準モデルに合わない
- ToBe：ERPの出力から経営レポートまでを自動化するツールをコーディングエージェントで構築。BI導入より安く、業務ロジックを正確に反映。
- ベンダーニュートラル：ログラスやAdaptive Planningで要件が満たせるならそちらを導入すべき。スクラッチが活きるのは管理会計の粒度がSaaSに合わない場合。

#### テーマ②：予実管理がExcelから脱却できない構造的な理由

- 対象読者：経営企画・FP&A担当
- AsIs：ERPは実績を持っているが、予算策定と予実対比はExcelに逃げがち。特に部門別・プロジェクト別は粒度が合わない。
- v2追記：直近のクライアント議論で「事業部門のコミットメントがないまま保守的な財務計画を策定する」「ドライバーベース計画が不在」「予実差異の原因特定に時間がかかる」という生の課題が確認されている。これを記事の導入部に活かせる。

#### テーマ③：SFAとERPの間に落ちる受注プロセス

- 対象読者：営業企画・営業事務マネージャー
- AsIs：営業がSFAに商談情報→受注後に経理がERPに手入力。間にExcelの受注台帳。
- ETLとの使い分け：単純にデータを流すだけならETL（ASTERIA Warp等）で十分。バリデーションロジック＋エラー管理UIが必要な場合はスクラッチ優位。

#### テーマ④：人事・労務のマスタが3箇所に散らばっている問題

- 対象読者：人事部長・総務部長
- ETLとの使い分け：承認フローが不要で単純同期ならETLが正解。承認フロー＋変更履歴管理＋不整合検知ダッシュボードが必要ならスクラッチ。

#### テーマ⑤：見積書・請求書のExcel職人問題

- 対象読者：営業管理・経理
- AsIs：ERPに販売管理があるのに、顧客ごとのフォーマット要件が異なるためExcelで作り直し。

#### テーマ⑥：製造業の原価計算が月末まで確定しない問題

- 対象読者：製造業の経理部長・管理会計担当（年商50-300億円、多品種少量生産）
- AsIs：生産管理システムの製造実績→月末にCSV→Excelで標準原価と実際原価の差異を品目別計算→配賦基準按分→原価差異分析レポート作成。経理2名で月末から翌月10営業日。年間約120人日。

### カテゴリ2：SaaS/ETLとの比較テーマ（信頼構築用）

#### テーマ⑦：経営ダッシュボードはBIで十分か、スクラッチで作るべきか

- 結論：定型レポートの可視化はBI。非定型の分析ロジック（独自KPI計算、複数ソースの結合ルール）が必要ならスクラッチ。

#### テーマ⑧：kintoneで業務システムを作るのが本当にベストなのか？ ← v3で全面改訂

- タイトル候補：「kintoneで業務システムを作るのが本当にベストなのか？」
- 切り口：kintone名指し批判ではなく「内製 vs 外部委託」フレームで3パターンを比較。kintoneはその一例。「kintoneが悪いのではなく、使い方の問題」のトーンを一貫。
- 3パターン比較（36ヶ月TCO、300万円相当の中規模業務システム・ユーザー20名）：
  - ①kintone内製：約560万円（社員の構築・保守負荷が大。本業を圧迫）
  - ②kintone外注（伴走あり）：約860-1,060万円（ライセンス＋外注＋伴走の三重課金。最も割高）
  - ③マネージドスクラッチ（月額制）：約575万円（初期費用ゼロ・月額制・解約自由。社員負荷ほぼゼロ。機能制限なし）
- ②の存在がこの比較の鍵。①と③だけだと「安い vs 高い」の二択に見えるが、②を挟むことで「kintoneも外注したら高い。しかも機能制限がある」が可視化される。
- kintoneでは実現困難な機能一覧（リアルタイム在庫、複雑な価格計算、基幹リアルタイム連携、帳票の細かいレイアウト制御、大量データ高速処理、フィールド単位の権限制御）を具体的に記載。
- 本質的な比較軸：最終的にクライアントが比較するのは「今のExcel運用を続けるコスト」と「システム化するコスト」。月額の費用は派遣社員1名の人件費や属人作業の年間コストと比較されるべき。
- ※ BusinessModel_ManagedScratch.mdの数値をベースに構成。

#### テーマ⑨：ETLツールで十分な連携、スクラッチが必要な連携

- ASTERIA Warp / DataSpiderの守備範囲とスクラッチの使い分け
- 結論：連携が5本以上ならETLがTCO有利。1-2本で複雑なバリデーション＋UIが必要ならスクラッチ。

### カテゴリ3：業界特化テーマ

#### テーマ⑩：卸売業の与信管理が属人化している問題

- 対象読者：卸売業の営業部長・経理部長

#### テーマ⑪：物流業の配車計画がExcel職人に依存している問題

- 対象読者：物流業の運行管理者・物流部長

#### テーマ⑫：小売業のMD計画と在庫管理のギャップ

- 対象読者：小売業のMD・バイヤー・在庫管理

#### テーマ⑬：建設業の工事台帳と原価管理の分断

- 対象読者：建設業の工事部長・経理
- v2追記：ブランディング戦略チャットで追加された業界テーマ。工事進捗と原価の日次連動、完成工事高の予測と実績差異の早期検知。

#### テーマ⑭：不動産管理業の契約更新管理が漏れる問題

- 対象読者：不動産管理会社のPM部門

#### テーマ⑮：百貨店・SCのテナント精算処理の複雑さ（v2で追加）

- 対象読者：商業施設の管理部門
- ブランディング戦略チャットで追加。精算ロジックがテナント契約ごとに異なり、SaaSの標準モデルでは吸収できない典型例。

### カテゴリ4：AI時代のコンサルタント価値系（v2で新設）

#### テーマ⑯：AIがコードを書く時代に、なぜ要件定義は自動化できないのか

- 切り口：AIコーディングエージェントの実力と限界を業務システム開発の文脈で具体的に解説
- 結論：AIが実装を加速するほど、「何を作るか」の精度が決定的に重要になる。要件の抽出は業務の暗黙知に依存するため、AIだけでは完結しない。

#### テーマ⑰：なぜ業務システムを「買う」のをやめたのか ── 月額制マネージドスクラッチという選択肢 ← v3で全面改訂

- 切り口：買い切りモデル（初期費用数百万円＋保守費用）のリスク構造を解説し、月額制モデル（初期費用ゼロ・月額課金・解約自由）との対比を描く
- 買い切りのリスク：初期投資が大きい → 失敗した場合のサンクコスト、保守が別契約 → 放置されがち、仕様変更に追加費用 → 硬直化
- 月額制のメリット：初期費用ゼロで始められる → 部長決裁圏内、解約自由 → リスクはサービス提供者側、保守込み → 常に最新の状態を維持
- 3年TCO比較：買い切り（初期300万＋保守月5-8万 = 約480-590万円）vs マネージドスクラッチ（575万円/3年）→ ほぼ同額だが、月額制は初期リスクゼロかつ保守込み
- 安定稼働後は月額半額（連続3ヶ月間、重大障害ゼロが条件）→ 品質にコミットするインセンティブがサービス提供者側にある
- フェーズリリースと段階課金：Month 1-2は開発中で0円、Phase 1リリースから課金開始 → 使える状態になってから払う
- 「SIerの見積もりが高すぎて動けない」企業に対して「初期費用ゼロの月額制なら予算確保のハードルが下がる」というメッセージ

#### テーマ⑱：日本のSIer構造はなぜ生まれたのか、AIでどう変わるのか

- 切り口：米国のユーザ企業内製文化 vs 日本の外注文化の構造差。AIがこの構造を壊し始めている。
- ポジショニングとの関係：「コンサルでもSIerでもない第三のポジション」がなぜ今の時代に必要かを歴史的文脈で説明。
